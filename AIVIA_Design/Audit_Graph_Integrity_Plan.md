## 1. The law this creates (for ratification)

**THE BIRTH-EDGE LAW: no node is alone.** Every node was deduced
from something, and that deduction is a TRAVERSABLE EDGE — every
node answers "why do you exist?" by walking, not by reading prose
properties. This is the L0 lineage guarantee ("never silently
absent") finally applied to the governance world with the same
rigor the SQL world already has (resolves_to, draws_from,
conservation).

**Census 1 upgrades.** The reachability census's equation
(`reachable ⊎ ruled-isolated == total`) DIES — its exemption list
was clerk-authored rulings, and Sunny's review of the very first
two rows (term, usage) overruled them both. The successor, THE
CONNECTION CENSUS:

```
birth-edged ⊎ counted-missing(OPEN-engine) ⊎ rooted == total nodes
```

- **birth-edged**: the node's origin edge exists and is walkable.
- **counted-missing**: the edge SHOULD exist and doesn't yet —
  honest engine debt, counted per kind, visible in the gap-check
  report (never ruled silent).
- **rooted**: the estate root(s) themselves (registration) — the
  only nodes allowed to be origins rather than have them; each
  such row individually Sunny-ruled.

**Closed at birth**: a NEW node kind must declare its birth edge in
the Connection Ledger before its first write, or the census fails —
the Gap_Classes/Speech_Sources pattern.

## 4. The initial review (one-time sweep to POPULATE the ledger; read-only)

Scan every node kind in the store + every pseudo-node the adjacency
conjures; per kind produce one verdict row:

- **kinds**: db, schema, table, column (KG1) · meaning_twin + twin
  interiors (KG2b) · file/scope/condition/derived-column
  (tree-borne pseudo-nodes — their node-vs-tree status is itself a
  review question for Sunny) · description, term, responsibility,
  disposition, usage, proposal, redaction, run_event (KG3) ·
  concept (KG4) · registration, extract_receipt, exclusion ·
  person (MISSING as a kind — authors are strings; the user-tree
  design needs person nodes; this review names the gap formally)
- **per kind, four answers**: (1) what deduced it into existence?
  (2) is that stored as data today (property/basis/anchor)? (3) is
  it WALKABLE (in the adjacency)? (4) verdict: edged /
  in-data-but-unwalkable / missing-in-data / rooted-candidate.
- Known findings the review will formalize: usage = in-data-but-
  unwalkable (about/author stored; adjacency blind); term =
  missing-in-data (append_term has no origin parameter; the ED
  vocab term cites nothing); persons = missing kind; descriptions/
  dispositions = anchored-but-unwalkable (anchors are strings the
  adjacency ignores).
- Output: **Audit_Graph_Integrity_Review.md** — the classified table =
  the draft Connection Ledger, one verdict per row for Sunny.
